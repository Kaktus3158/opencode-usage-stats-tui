# opencode-usage-stats-tui

Статистика расхода токенов для терминального интерфейса [OpenCode](https://opencode.ai): запросы, токены и стоимость в разрезе **моделей**, **сессий** и **дней**.

У OpenCode есть встроенный `/stats` с календарём активности, но он не показывает, **какие именно** модели и сессии съели токены. Этот плагин добавляет недостающую детализацию — и берёт те же данные, что уже есть на сервере OpenCode: без аккаунта, без пароля и без внешних сервисов.

## Возможности

| | |
|---|---|
| **Три вида** | по моделям, по сессиям, по дням — переключаются одним нажатием |
| **Любой период** | 24 часа, 7 дней, 30 дней или произвольный диапазон дат |
| **Полная детализация** | запросы, токены, входящие, исходящие, кеш и стоимость в каждой строке |
| **Сортировка по релевантности** | модели идут в порядке последнего использования |
| **Только локально** | читается API вашего собственного инстанса OpenCode, ничего не уходит наружу |
| **Без зависимостей** | плагин собирается самим OpenCode во время выполнения |

## Установка

У плагина есть и серверная, и TUI-часть, поэтому всё настраивается одной командой:

```sh
opencode plugin add github:Kaktus3158/opencode-usage-stats-tui
```

Команда клонирует репозиторий и добавляет плагин в глобальный `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["github:Kaktus3158/opencode-usage-stats-tui"]
}
```

Если хотите настроить вручную — добавьте ту же строку в `~/.config/opencode/opencode.json`: TUI подхватит TUI-часть плагина из списка, который ведёт сервер.

Пакет есть и в npm — если хотите ставить released-версию:

```sh
opencode plugin add opencode-usage-stats-tui
```

После перезапуска OpenCode откройте страницу:

```
/tokens
```

> Интерфейс плагина написан по-русски — на языке автора. Английская версия делается
> небольшим изменением, скажите, если нужно.

## Использование

Наберите `/tokens` в промпте или выберите **Token usage (24h)** в палитре команд (`ctrl+p`).

| Клавиша | Действие |
|---|---|
| `r` | обновить данные |
| `v` | сменить вид: модели → сессии → дни |
| `d` | выбрать период: 24 часа / 7 дней / 30 дней / свои даты |
| `esc` | назад в сессию, из которой открыли |

При выборе **своих дат** запрашиваются начало и конец периода. Понимаются форматы `ДД.ММ.ГГГГ`, `ДД.ММ`, `ГГГГ-ММ-ДД` и `ДД.ММ.ГГГГ ЧЧ:ММ`; последний день включается целиком.

## Откуда берутся цифры

Всё берётся из API того инстанса OpenCode, который вы запустили:

- **Итоги и разбивка по моделям** — `GET /api/experimental/session/stats`, тот же эндпоинт, что использует встроенный постер `/stats`.
- **Разбивка по сессиям и дням** — в stats API её нет, поэтому она считается по assistant-сообщениям всех сессий. Их `tokens` и `cost` в сумме точно совпадают с агрегатами stats API (проверено на живых данных).
- **Когда модель использовалась в последний раз** — stats API этого не отдаёт. Время восстанавливается из сообщений `model-switched` в истории сессии: замена модели в момент *t* означает, что предыдущая использовалась до *t*, а новая — с *t*.

Никакие учётные данные не читаются, URL не подбирается, база данных не открывается: плагин обращается к серверу через клиент, который передаёт сам OpenCode.

## Требования

- OpenCode **2.2.0** или новее
- Терминал шириной хотя бы 60 колонок

## Разработка

```sh
git clone https://github.com/Kaktus3158/opencode-usage-stats-tui
cd opencode-usage-stats-tui
npm install
npm run check          # проверка типов + сборка
npm run install:local  # скопировать исходники в ~/.config/opencode/plugins/usage
```

`npm run compile` компилирует `src/` в `dist/` тем же Solid-трансформом, который OpenCode применяет к локальным плагинам. Этот шаг обязателен: внутри `node_modules` OpenCode Solid-трансформ не запускает, поэтому опубликованный `.tsx` потерял бы реактивность.

Скрипт сборки назван `compile`, а не `build`, намеренно: при установке git-зависимости npm выполняет `npm install` внутри клона, если в пакете есть скрипт `build`, `install`, `prepare` или `postinstall` — именно эта подготовка ломает установку git-плагинов в OpenCode.

Собранный `dist/` лежит в репозитории намеренно: OpenCode ставит пакеты плагинов без выполнения скриптов, поэтому `prepare` не отработал бы и пакет пришёл бы без сборки. После правки исходников выполните `npm run compile` и закоммитьте результат; CI падает, если сборка в репозитории разошлась с исходниками.

В папке `standalone/` лежит отдельная маленькая программа, которая рисует ту же таблицу в своём окне. В published-пакет она не входит.
